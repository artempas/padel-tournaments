# Деплой на Synology NAS

Приложение запускается одним контейнером и подключается к вашему существующему
PostgreSQL. Схема применяется автоматически при старте.

---

## ⚠️ Сначала прочитайте это

**Passkey работает только по HTTPS.** Единственное исключение — `localhost`.
Если открыть приложение по адресу вида `http://192.168.1.50:3000`, страница
загрузится, но кнопка входа будет падать с ошибкой: браузер просто откажется
создавать passkey. Обойти это нельзя — так устроен стандарт WebAuthn.

Поэтому **шаг 1 обязателен**: нужен домен и сертификат. Если вы планировали
пользоваться приложением только в локальной сети по IP, авторизация не заработает.

Второе: **passkey привязан к домену** (`RP_ID`). Если позже сменить адрес, все
созданные passkey перестанут подходить и организаторам придётся регистрироваться
заново. Выберите адрес один раз.

---

## Что понадобится

- Synology NAS с **Container Manager** (DSM 7.2+) или пакетом **Docker** (DSM 7.0–7.1)
- Работающий **PostgreSQL 13 или новее**
- Права администратора DSM и доступ к настройкам роутера

---

## Шаг 1. Домен и HTTPS

### 1.1. Адрес через Synology DDNS

**Панель управления → Внешний доступ → DDNS → Добавить**

- Поставщик услуг: `Synology`
- Имя хоста: например `artem` → получится `artem.synology.me`
- Внешний адрес: определится автоматически

Приложение будет жить на поддомене, например `padel.artem.synology.me`.

Если у вас есть собственный домен — используйте его, шаги дальше те же.

### 1.2. Проброс портов на роутере

Пробросьте на IP вашего NAS:

| Внешний порт | Внутренний порт | Зачем |
| ------------ | --------------- | ----- |
| 80           | 80              | Выпуск и продление сертификата Let's Encrypt |
| 443          | 443             | Собственно доступ к приложению |

Порт 80 нужен именно для проверки владения доменом. Без него сертификат
не выпустится и через 90 дней не продлится.

### 1.3. Сертификат Let's Encrypt

**Панель управления → Безопасность → Сертификат → Добавить → Получить сертификат
от Let's Encrypt**

- Имя домена: `padel.artem.synology.me`
- Email: ваш

DSM продлевает такой сертификат сам.

### 1.4. Обратный прокси

**Панель управления → Портал входа → Дополнительно → Обратный прокси-сервер → Создать**

| Поле | Значение |
| ---- | -------- |
| Источник — протокол | `HTTPS` |
| Источник — имя хоста | `padel.artem.synology.me` |
| Источник — порт | `443` |
| Назначение — протокол | `HTTP` |
| Назначение — имя хоста | `localhost` |
| Назначение — порт | `3000` |

Затем в **Безопасность → Сертификат → Настройки** сопоставьте
`padel.artem.synology.me` с выпущенным сертификатом.

## Шаг 2. База данных

Подключитесь к вашему PostgreSQL и создайте отдельную базу и пользователя —
приложению не нужны права на остальные ваши базы:

```sql
CREATE ROLE padel WITH LOGIN PASSWORD 'придумайте_пароль';
CREATE DATABASE padel OWNER padel;
```

Таблицы создавать вручную не надо — контейнер применит схему при старте.

Убедитесь, что PostgreSQL слушает не только `localhost`, иначе контейнер до него
не достучится. В `postgresql.conf` должно быть `listen_addresses = '*'`,
а в `pg_hba.conf` — разрешение для подсети Docker.

## Шаг 3. Файлы на NAS

Создайте общую папку, например `docker/padel`, и положите туда содержимое проекта.

Через **File Station** или по SSH:

```bash
scp -r ./padel-tournaments admin@nas:/volume1/docker/padel
```

## Шаг 4. Настройки

В папке проекта на NAS создайте файл `.env` рядом с `docker-compose.prod.yml`
(за образец — `.env.production.example`):

```env
DATABASE_URL=postgres://padel:придуманный_пароль@host.docker.internal:5432/padel
RP_ID=padel.artem.synology.me
ORIGIN=https://padel.artem.synology.me
RP_NAME=Падел Турниры
```

Вход через Яндекс ID добавляется двумя строками — см. ниже, он необязателен.

Про `DATABASE_URL` — выберите форму под то, где живёт ваш PostgreSQL:

| Где PostgreSQL | Хост в строке подключения |
| -------------- | ------------------------- |
| В Docker, порт опубликован на NAS | `host.docker.internal:5432` |
| В Docker, общая сеть с приложением | `имя-контейнера:5432` (см. комментарий в `docker-compose.prod.yml`) |
| На другой машине в сети | `192.168.1.50:5432` |

Про `RP_ID` и `ORIGIN`:

- `RP_ID` — **только имя хоста**: без `https://`, без порта, без слэша в конце
- `ORIGIN` — **полный адрес**, ровно как его показывает браузер
- `RP_ID` должен совпадать с доменом из `ORIGIN` либо быть его родительским
  доменом. `synology.me` использовать нельзя — это публичный суффикс

### Вход через Яндекс ID (необязательно)

Без этих двух строк в `.env` кнопки «Войти с Яндекс ID» просто не будет, а
passkey работает как обычно:

```env
YANDEX_CLIENT_ID=идентификатор_приложения
YANDEX_CLIENT_SECRET=секрет_приложения
```

Приложение заводится на https://oauth.yandex.ru — тип «Для авторизации
пользователей», платформа «Веб-сервисы». Прав выдавать не нужно: приложению
хватает идентификатора и логина, которые Яндекс отдаёт и без них.
Redirect URI должен совпасть с адресом сайта **точно**, включая схему и путь:

```
https://padel.artem.synology.me/api/auth/yandex/callback
```

Он собирается из `ORIGIN`, поэтому отдельная переменная не нужна. Она
понадобится, только если в `ORIGIN` перечислено несколько адресов и
зарегистрирован в Яндексе не первый из них — тогда задайте
`YANDEX_REDIRECT_URI` полностью.

Боевое приложение стоит завести отдельно от того, с которым вы пробовали вход
на `localhost`: Redirect URI у них разные, а смешивать окружения в одном
приложении Яндекс не советует.

## Шаг 5. Запуск

**Container Manager → Проект → Создать**

- Название проекта: `padel`
- Путь: папка из шага 3
- Источник: `Использовать существующий docker-compose.yml`
- Выберите `docker-compose.prod.yml`

Нажмите **Создать**. Первая сборка занимает 5–15 минут — NAS компилирует
приложение.

> **Если сборка падает по нехватке памяти.** Сборка Next.js требует около 2 ГБ
> RAM. На слабых моделях соберите образ на компьютере и перенесите готовым:
>
> ```bash
> # на компьютере
> docker build -t padel-tournaments:latest .
> docker save padel-tournaments:latest | gzip > padel.tar.gz
> ```
>
> Загрузите `padel.tar.gz` на NAS, затем **Container Manager → Образ →
> Добавить → Добавить из файла**. После этого уберите секцию `build:` из
> `docker-compose.prod.yml`, оставив только `image:`.

## Шаг 6. Проверка

В **Container Manager → Контейнер → padel-app → Журнал** должно быть:

```
Applying migration `20260727000000_schema_v2`
All migrations have been successfully applied.
Starting Padel Tournaments on port 3000 (RP_ID=padel.artem.synology.me, ORIGIN=https://padel.artem.synology.me)
 ✓ Ready in 243ms
```

> **Первое обновление на схему v2.** Если база уже работала со схемой v1, её
> надо один раз пометить как размеченную, иначе миграция попытается создать
> уже существующие таблицы:
>
> ```bash
> docker exec padel-app node ./node_modules/prisma/build/index.js \
>   migrate resolve --applied 20260726000000_baseline_v1
> ```
>
> После этого обычный старт контейнера сам применит миграцию v2 и перенесёт
> данные. Она выполняется одной транзакцией и начинается с проверок: если
> накопленные данные не проходят новые ограничения, миграция откатится
> целиком с понятным сообщением, а база останется в состоянии v1.
> **Сделайте бэкап перед первым запуском.**

Откройте `https://padel.artem.synology.me` с телефона, зарегистрируйтесь по
passkey и создайте турнир. Телефон предложит Face ID, отпечаток или PIN.

У контейнера есть healthcheck — статус в Container Manager должен стать
`healthy` в течение минуты.

## Обновление

```bash
cd /volume1/docker/padel
git pull                      # или залейте новые файлы
docker compose -f docker-compose.prod.yml up -d --build
```

Или в Container Manager: **Проект → padel → Действие → Собрать заново**.

Схема применяется автоматически и повторный запуск безопасен — данные не теряются.

## Резервное копирование

Все данные лежат в PostgreSQL, у контейнера своего состояния нет:

```bash
pg_dump -U padel -d padel > padel-$(date +%F).sql
```

Полезно добавить это в **Планировщик задач** DSM.

## Если что-то не работает

**Кнопка входа ничего не делает или ошибка «Домен не разрешён для passkey».**
`RP_ID` не совпадает с доменом в адресной строке. Проверьте, что там имя хоста
без `https://` и без порта, и что вы открываете сайт именно по HTTPS.

**Вход не предлагается на телефоне, хотя на компьютере работает.**
Скорее всего сайт открыт по HTTP или по IP. Passkey требует HTTPS.

**Контейнер перезапускается по кругу.**
Смотрите журнал. Если там `Database not ready` — контейнер не видит PostgreSQL:
проверьте `DATABASE_URL`, `listen_addresses` и `pg_hba.conf`. Приложение делает
10 попыток с интервалом 5 секунд, потом останавливается.

**`PostgreSQL 12 detected — version 13 or newer is required`.**
Схема использует `gen_random_uuid()`, встроенный с версии 13. На более старом
сервере выполните `CREATE EXTENSION pgcrypto;` в базе `padel` и перезапустите
контейнер.

**Сайт открывается, но выглядит без оформления.**
Это бывает при сборке поверх запущенного дев-сервера, а не в Docker. В контейнере
такого не случается — статика собрана внутрь образа.

**Сертификат не выпускается.**
Порт 80 не проброшен на NAS либо занят провайдером. Проверьте, что снаружи
`http://padel.artem.synology.me` доходит до NAS.
